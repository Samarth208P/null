## Artifact handling

The circuit/compiler pair is Noir **1.0.0-beta.22** with Barretenberg **5.0.0-nightly.20260522**, using the EVM verifier target. The generated Solidity is real ZK verifier output; generation is not evidence that the complete proving/submission path works. Artifact checksums are recorded in generated manifests instead of duplicated in this document. Rebuilding source requires regenerating and retaining the corresponding circuit, verification key, Solidity verifier, ABI, and runtime-code evidence together.

The checked-in deployment template intentionally retains `status: "awaiting-artifacts"` and null addresses/hashes. It is an example, not an automatically updated report of local compiler output. Only the deployment script writes a manifest with actual deployed addresses. See [deployment instructions](DEPLOYMENT.md), [contract development](../contracts/README.md), and [circuit development](../circuits/README.md).

## Release boundary

This is an unaudited testnet prototype. No test suite, security audit, privacy audit, sponsor qualification, or production-readiness assessment was performed. Compilation does not establish conservation, authorization correctness, cryptographic compatibility, reliable recovery, or resistance to malicious inputs. Those remain release work rather than completed development evidence.

The MVP has **no withdrawal route**. A claim creates a private note; it does not transfer ERC-20 tokens to a recipient wallet. Public deposits expose their wallet, amount, and timing. The local sandbox uses sample funds and local state and must not be represented as a successful onchain or sponsor demonstration. See [privacy guarantees](PRIVACY_GUARANTEES.md), [sponsor compliance](SPONSOR_COMPLIANCE.md), and [security policy](../SECURITY.md).
