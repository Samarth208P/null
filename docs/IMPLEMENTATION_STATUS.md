## Local configuration evidence

The only active environment file is the repository root `.env`; the former deployment, web, and service environment files were removed only after value and wallet-preservation checks. The file has a protected current-user Windows ACL and is ignored by Git. Vite exposes only `VITE_` settings. Direct HTTP requests for the actual environment and private artifacts were denied. An internal scan of 321 production browser files found zero occurrences of the three populated private-key/secret values; none were printed.

`pnpm dev:all` starts the web application at `http://127.0.0.1:5173` and the local relayer at port 8787. The default configured workspace is Sepolia. Treasury policy creation and registration succeeded using the [local treasury CLI](../tools/TREASURY.md); the policy opening remains in protected local storage for browser import. A separate signer approves raw distribution intents, so this path does not require Privy. Initial contract deployment consumed 0.026342219484077175 Sepolia ETH; policy registration consumed 0.00162231983264676. Relayer funding is a transfer between local test wallets, not a service charge.

## Artifact handling

The Sepolia deployment preflight also executed all eight constructors through read-only RPC state overrides at block **11,645,250**. Every constructor returned runtime code and a gas estimate; the combined allowance including a 20% gas margin was **29,197,240 gas**. Hypothetical funding and contract code existed only inside those RPC simulations. This does not execute a proof, submit a transaction, or establish an actual deployment.

The circuit/compiler pair is Noir **1.0.0-beta.22** with Barretenberg **5.0.0-nightly.20260522**, using the EVM verifier target. The generated Solidity is real ZK verifier output; generation is not evidence that the complete proving/submission path works. Artifact checksums are recorded in generated manifests instead of duplicated in this document. Rebuilding source requires regenerating and retaining the corresponding circuit, verification key, Solidity verifier, ABI, and runtime-code evidence together.

The checked-in deployment template intentionally retains `status: "awaiting-artifacts"` and null addresses/hashes. It is an example, not an automatically updated report of local compiler output. Only the deployment script writes a manifest with actual deployed addresses. See [deployment instructions](DEPLOYMENT.md), [contract development](../contracts/README.md), and [circuit development](../circuits/README.md).

## Release boundary

This is an unaudited testnet prototype. No test suite, security audit, privacy audit, sponsor qualification, or production-readiness assessment was performed. Compilation does not establish conservation, authorization correctness, cryptographic compatibility, reliable recovery, or resistance to malicious inputs. Those remain release work rather than completed development evidence.

The v0.2 pool implements full-note withdrawals and approved treasury refunds. A claim creates a private note; withdrawal is a separate proof-authorized ERC-20 transfer. The immutable v0.1 pool cannot withdraw. See [withdrawal verification](WITHDRAWAL_VERIFICATION.md) for the exact test scope. Public deposits expose their wallet, amount, and timing. The local sandbox uses sample funds and local state and must not be represented as a successful onchain or sponsor demonstration. See [privacy guarantees](PRIVACY_GUARANTEES.md), [sponsor compliance](SPONSOR_COMPLIANCE.md), and [security policy](../SECURITY.md).
